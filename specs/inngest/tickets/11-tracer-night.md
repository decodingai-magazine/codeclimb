# 11: Tracer night: one mock round on the Inngest dev server

**What to build:** The first night that works end to end. `run-night` validates the config, starts the night and follows its rows. The worker is one long-running process holding all of CodeClimb's logic; its API is up as soon as it starts, and the Inngest dev server drives the night by calling it. A night runs init, rounds (experiment, dev evaluation, keep or revert, row), then the test evaluation of the checkpoint and `done.json`. The review, notes, send-backs, metering, the noise run, most soft stops and the hard stop come in later tickets.

**Spec sections** (`specs/inngest/spec.md`): "Goal and done signal", "Architecture", "Features" (Loop; Mock mode), "Services", "CLI", "Ids and names", "Files a night writes", "Result row", "Environment", "Runtime and tools", "Numbers"

**Blocked by:** 04 (Decision functions: weighted score, keep rule, noise margin, stop order); 05 (Result rows: schema, deduplicated append, validate-results); 09 (Coder experiment: from the prompt to one commit); 10 (Evaluator: one commit scored on dev or test in its own sandbox)

**Status:** ready-for-agent

- [ ] `npm run worker` starts one long-running process. Its API listener (`CODECLIMB_API_HOST`, `CODECLIMB_API_PORT`, default `127.0.0.1:7421`) answers `GET /api/nights` with a status below 500 before the dev server is up, with no `.env` and no `runs-inngest/` folder. Started together, `npm run dev:inngest` and `npm run worker` both answer within 60 s, and a worker started again answers within 60 s. Ticket 32 fills in the rest of the API
- [ ] A dev server started by the given `dev:inngest`, which looks for the worker's Inngest endpoint at `http://localhost:3000/api/inngest` with auto-discovery off, runs the worker's functions, also when it was already running before the worker started. With `INNGEST_DEV` unset, the CLI and the worker use the local dev server on 8288
- [ ] The durable runtime never runs CodeClimb's code itself; it calls the worker. The night starts each experiment and each evaluation as work of its own and waits for it, so a failure of one is the round's outcome (an `error` row), not the night's end; work that fails or is interrupted is tried again
- [ ] Init builds the coder's bundle in `nights/<id>/bundle/`, imports the starter as `<night>-r0-starter`, and writes `night.json` with `night_id`, `startedAt`, `deadlineMs`, the round-0 experiment, `seed`, the resolved `config`, `metric_script_sha256` and `lessons_sha256`
- [ ] A round runs the experiment `<night>-r<N>-e0` from the checkpoint, its dev evaluation `<exp>-eval` (not run when the repository check reported errors: the experiment is then an `error`), the keep rule, and records the row with every field of "Result row" (`coder_usd`, `dev_usd`, `program_usd`, `reviewer_usd`, `tokens`, `wall_s`, `infra_errors` included). The starter is never run on dev; a reverted experiment is dropped and the next round starts from the same checkpoint
- [ ] On a soft stop (here `max_rounds` and `thresholds`) the checkpoint, or the starter when nothing was kept, is scored once on test as `<night>-test-r<N>`; the `test` row is recorded; `done.json` holds `night_id`, `stop_reason`, `rounds`, `kept` (`exp_id`, `commit`, `dev_score`), `test_metrics`, `spend_usd` and `finished_at`; no `cc-<id>` sandbox is left
- [ ] `run-night` starts the night under `--night-id` or the default id; a start with a used id starts nothing. Following prints new rows as they land, then `done` as the first word of a line of its own, and exits 0; `--no-wait` exits 0 within 120 s of the start; Ctrl-C detaches and the night keeps running
- [ ] A night that fails, however early (also before `night.json` exists), ends with `nights/<id>/stop.json` with reason `failed` and its sandboxes removed; a following `run-night` prints `stopped` and exits 0, so it never hangs. Ticket 21 completes the hard stop
- [ ] With the dev server and the worker up, `npm run run-night -- --config configs/datenorm-smoke.yaml --mock --rounds 1 --night-id <id>` reaches round 1 within 120 s and prints `done` with `stop_reason` `max_rounds` within 300 s, writing to `runs-inngest/mock/datenorm-smoke/`
- [ ] For that night C2, C3, C4, C5, C10, C12 and C14 of "Goal and done signal" hold; `code-state.json` has `stop: done` and `session/` holds a session file; round 1 holds the starter's code, scores accuracy 0.125 on dev and is kept
